# Portfolio Project System

This folder tracks the project roadmap for the public portfolio. The goal is to build one strong proof project at a time, document the frontend and backend separately, and only move to the next project when the current one is strong enough to show publicly.

## Active Priority

The active project is:

`01-launchbill-saas-subscription-billing-platform`

No other project should move into implementation until LaunchBill has a working frontend, working REST API backend, tests, deployment notes, screenshots, public repository, live URL, and a portfolio case study.

## Standard Project Folder Shape

Each project has:

- `README.md` for the product idea and value.
- `PROJECT_CHECKLIST.md` for the project completion gate.
- `frontend/` for pages, components, UX, and browser testing notes.
- `backend/` for REST API, database, auth, payments, jobs, and backend tests.
- `docs/` for case studies, portfolio copy, screenshots, and deployment notes.

## Portfolio Proof Rule

A project is not finished when the code works. It is finished when another person can understand what was built, why it matters, how it works, and how to review it.
